Own `backend/` (the Python API) and `deploy/` (the server stack). Reuse v3 `server/` patterns by COPYING into `backend/` — never edit the `server/` reference.

Contracts (honor, do not redefine): REST/WS API contract (`backend/API_CONTRACT.md`, wire shapes mirror v3 `live_message_batch` + `status`), `engine/config.schema.json`, and the engine binding API (`AGENTS.md`) exposed by `can_engine` (the nanobind module from the engine-binding track).

Deliverables — `backend/`:
- REST + WS API (FastAPI + async). REST: config CRUD, MDC spec CRUD, start/stop, status. WS: push `live_message_batch` + `status` envelopes; handle `request_cache`/`reset_cache`.
- An async loop that pulls decoded batches from the engine module (`EngineHandle.poll_batch`) and fans them out to WS clients + sinks.
- **Sinks** behind one small `Sink` protocol: InfluxDB (default), SQLite (local/no-Docker), file. Adding a sink is Python-only. Keep writes async/batched.
- Lean deps for packaging (no pandas/numpy in the desktop path; heavy analytics are server-only optional extras). Compile with **Nuitka** (`--standalone`/`--onefile`) to a native binary bundling the `can_engine` module — smaller/faster than PyInstaller.

Deliverables — `deploy/`:
- `deploy/docker-compose.yml`: backend (headless) + Grafana + DB (InfluxDB default). Local no-Docker mode uses SQLite.
- Grafana provisioning (datasources + dashboards generated by `mdc2grafana` where possible).
- `role: server` vs `role: desktop` config handling against `engine/config.schema.json`.

Follow `.cursor/rules/backend.mdc` and `.cursor/rules/deploy.mdc`. Before finishing: the app boots (uvicorn), a smoke test exercises a WS envelope + one REST route, and `docker compose config` validates. Document how to run it.
