# Wave 4 — Readability Review: canspec-ui (MDC v3)

## Findings

can/canspec-ui/src/data.ts:17 — `MdcConversion.is_float` is typed `boolean | undefined`, but the contract (§5) says `conversion` only exists for `rational|table` kinds — neither carries `is_float`. This field is never populated in practice and will always map to `undefined`, silently producing `isFloat: undefined` on the view-model `SignalConversion`. Suggested fix: remove `is_float` from `MdcConversion`; `isFloat` on the view-model conversion object is redundant anyway since the signal-level `sig.is_float` already drives `CanSignal.isFloat`.

can/canspec-ui/src/data.ts:113 — `buildValueTableIndex` takes rest params named `groups` but callers always pass exactly two args (net tables then project tables). The rest-param form implies arbitrary arity that doesn't exist; it also hides the merge order (net wins over project, because the second write overwrites the first). Suggested fix: use two explicit params `(netTables, projectTables)` and iterate them in declared order, then document the priority with a single inline comment.

can/canspec-ui/src/data.ts:123-132 — `mapConversion` returns `{ kind: "identity" }` when `conv` is `undefined`, but per the contract (§5) `conversion` is only present on rational/table signals — an absent `conversion` is the *normal* case for linear signals, not an "identity" sentinel. Naming the fallback `"identity"` imports a term that was explicitly retired from the v3 schema. Suggested fix: rename fallback to `{ kind: "linear" }` or remove the `kind` field entirely from the fallback and let callers infer absence means linear.

can/canspec-ui/src/data.ts:178 — `mapMessage` parameter is named `networkName` but `busName` is the TS view-model field it populates. The parameter name and the field name diverge, making the assignment at line 193 (`busName: networkName`) mildly confusing. Suggested fix: rename the parameter to `busName` to match the output field.

can/canspec-ui/src/data.ts:201-219 — `mapNetwork` builds `valueTables` twice: once to create the lookup `Map` (line 202) and once to build the `CanNetwork.valueTables` array (lines 214-217). The second spread over `net.valueTables` re-calls `mapChoices` on the same entries. Suggested fix: derive `CanNetwork.valueTables` directly from the already-computed `Map` entries, or at minimum add a comment explaining the two passes serve different purposes (lookup vs. output array).

can/canspec-ui/src/data.ts:258-259 — The `ponytail:` comment says `smoke-map.mjs` uses the `mapVehicleDoc` export, but `smoke-map.mjs` never imports it — it does its own structural check (frame_id, start, length) without exercising the actual mapper. The comment creates a false expectation. Suggested fix: either wire `smoke-map.mjs` to import and call `mapVehicleDoc` (making the comment true), or update the comment to accurately describe what the export is for (e.g., "exported for testing or future tooling use").

can/canspec-ui/scripts/copy-mdc.mjs:14 — `stagedVehicleIds` is a `Set` used to de-duplicate across vehicles/ and examples/ directories, but its name doesn't reveal *why* it exists. Suggested fix: rename to `vehiclesAlreadyStaged` or add a one-line comment `// prevents examples/ from overriding real vehicle docs`.

can/canspec-ui/scripts/copy-mdc.mjs:29 — `relDest.replaceAll("\\", "/")` silently normalises Windows path separators. On the CI runner (Ubuntu) this is a no-op but on a Windows dev machine the index paths will be correctly normalised; however there is no comment explaining why. Suggested fix: add a brief inline comment `// normalise to forward-slash for JSON index portability`.

can/canspec-ui/scripts/copy-mdc.mjs:60-65 — The last-resort fallback at lines 60-65 copies a single hardcoded example (`lhr-ev1/project.mdc.json`) but then immediately re-checks `index.length === 0` at line 67 and exits with an error. This means: if the hardcoded example exists, the script succeeds silently with a single doc; if it doesn't exist, the error message (line 68) mentions `can/vehicles/ or can/mdc/examples/` but the dev just tried a third fallback path that the error message doesn't mention. Suggested fix: merge the two `if (index.length === 0)` blocks into one; log a warning when the last-resort path is used so the developer knows they are running on a fallback.

can/canspec-ui/scripts/smoke-map.mjs:37-43 — The structural check validates `frame_id`, `start`, and `length` per message/signal, but does not validate `schemaVersion` consistency within each network's messages (e.g., does not catch a mixed-version file where the root says 3.x but message fields use old names like `id` instead of `frame_id`). The check at line 33-35 guards the `frame_id` field, but a v2 doc that has `id` instead of `frame_id` will pass the `schemaVersion` check and then silently produce `frame_id: undefined` (the typeof check would catch it, but only at msg level). This is fine as-is but the intent of the smoke test is unclear: is it testing the *mapper* or the *doc shape*? Suggested fix: add a short header comment stating the script tests doc shape only (not the mapper), so reviewers don't assume mapper coverage.

can/canspec-ui/scripts/smoke-map.mjs:1 — Header comment says "fails if v3 fields are missing or mapper throws" but the mapper (`mapVehicleDoc`) is never imported or called. The "or mapper throws" clause is incorrect. Suggested fix: remove "or mapper throws" from the header comment.

.github/workflows/build-docs.yml:29-32 — **Stale reference to deleted file.** Step "Export CAN spec JSON" (line 29) runs `python3 can/canspec-ui/export_canspec_json.py`, which was deleted in this change set. The step has `continue-on-error: true` so CI will not break immediately, but it will log a misleading error on every run. The "Build CAN spec UI (Vite)" step at line 51 runs `npm run build`, which now includes `node scripts/copy-mdc.mjs` — so the old export step is both redundant and stale. Suggested fix: replace the "Export CAN spec JSON" step with `npm run copy-mdc` (or remove it entirely since `npm run build` already runs `copy-mdc`).

Embedded-Sharepoint/scripts/build-docs-with-canspec-ui.sh:10 — **Stale reference to deleted file.** The local build helper script calls `python3 "$CANSPEC_UI/export_canspec_json.py"`, which no longer exists. Suggested fix: replace line 10 with `npm --prefix "$CANSPEC_UI" run copy-mdc` (or `cd "$CANSPEC_UI" && npm run copy-mdc`).
